# Нотатки для розробників

Як [`bf2font.py`](../bf2font.py) перетворює `.mcm` від Betaflight на PNG та
файли шрифтів, і як запустити його на своїх шрифтах.

## Запуск

Залежності керуються через [uv](https://docs.astral.sh/uv/). Скрипт ще й має
вбудовані метадані PEP 723, тому запускається окремо звідки завгодно.

```bash
uv run bf2font.py original_fonts/default.mcm
```

```bash
uv run bf2font.py original_fonts/*.mcm -o output --scale 16
```

| Опція | Що робить |
| --- | --- |
| `-o, --output` | тека виводу (типово `output`) |
| `-s, --scale` | масштаб PNG; 1 піксель OSD = N пікселів зображення (типово `8`, тобто 96×144 на символ) |
| `--formats` | будь-яка підмножина з `otf,ttf,woff,woff2` |
| `--family` | точна назва гарнітури, лише для одного вхідного файлу |
| `--family-prefix` | префікс для назви (типово `Betaflight OSD`) |
| `--literal-ascii` | лишити `a-z` на їхніх слотах із символами, не зводити на великі літери |
| `--no-ascii-cmap` | мапити символи лише за `U+E000 + індекс` |
| `--no-layer-fonts` | не робити пласкі гарнітури `Shadow` і `Fill` |
| `--sets` | які зібрані набори будувати: будь-яка підмножина з `cyrillic,accents,greek,punctuation,blocks`, порожньо — жодного |

Вивід на кожен вхідний файл:

```
output/<name>/
├── png/000.png … 255.png    по одному PNG на символ, прозорий фон
├── png/<set>/0410.png …     по PNG на кожен зібраний символ, назва — кодпойнт
├── <name>_sheet.png         атлас 16×16 з усім набором
├── <name>_<set>.png         по атласу на кожен зібраний набір
├── <name>.json              символи, зібрані набори, розкладені символи, іконки
└── fonts/
    ├── otf/                 <Family>.otf, <Family>Shadow.otf, <Family>Fill.otf
    ├── ttf/                 ті самі три гарнітури
    ├── woff/
    └── woff2/
```

## Формат `.mcm`

Це дамп пам'яті символів MAX7456: рядок `MAX7456`, далі 16384 рядки по вісім
двійкових цифр, тобто 256 символів × 64 байти. Перші 54 байти символу це 12×18
пікселів по два біти, рядок за рядком. Решта 10 байтів це заповнювач (`0x55`).

| Значення | Піксель |
| --- | --- |
| `0b00` | чорний |
| `0b10` | білий |
| `0b01`, `0b11` | прозорий |

Саме через це кодування символ Betaflight білий із чорною обводкою, і саме
тому одноколірний шрифт не може передати його чесно.

## Пікселі → контури

З кожного символу виходить два набори пікселів: **силует** (чорні + білі) і
самі **білі** пікселі.

Обидва векторизуються трасуванням межі. Кожна клітинка додає ті одиничні
ребра, з іншого боку яких клітинки немає, орієнтовані так, щоб залита область
була ліворуч. Зчеплення таких ребер дає зовнішні контури проти годинникової
стрілки, а дірки за годинниковою, що правильно для правила ненульового
заповнення. Там, де дві клітинки дотикаються лише кутом, з однієї вершини
виходить кілька ребер, тож обхід бере найкрутіший поворот праворуч і контури не
перетинаються. Точки на одній прямій потім прибираються.

У TrueType напрямок контурів протилежний до PostScript, тому для `glyf`
контури розвертаються.

## Зібрані набори символів

Вихідний шрифт — це 256 символів: ASCII та іконки OSD. Усе інше намальовано з
форм, які в цьому шрифті вже є, і ніколи з констант: жирна гарнітура дістає
жирну пунктуацію, нахилена — нахилену діакритику. Усе це лежить у `scripts/`;
`bf2font.py` у корені — єдина точка входу.

| Модуль | Що додає |
| --- | --- |
| `scripts/shapes.py` | примітиви: `Geometry`, `render`, `box`, `ring`, `line`, `chevron`, `triangle`, `wave` |
| `scripts/cyrillic.py` | 37 великих літер кирилиці |
| `scripts/accents.py` | 67 великих латинських літер з діакритикою, плюс Ð Đ Ø Ł Þ |
| `scripts/greek.py` | 24 великі літери грецької |
| `scripts/punctuation.py` | тире, лапки, математика, валюти й п'ять ASCII-комірок, які у вихідному шрифті зайняті іконками або порожні |
| `scripts/blocks.py` | псевдографіка, півблоки, заливки, маркери |

Кожен модуль має ті самі дві точки входу — більше `bf2font.py` про нього не
знає:

```python
cores(latin)  -> {кодпойнт: множина білих клітинок}
glyphs(latin) -> {кодпойнт: пікселі 12×18, вже з обводкою}
```

`Geometry` міряє шрифт по його ж великих латинських літерах: товщину штриха,
колонки стійок, рядки перекладин і сходинку нахилу. Гліф, зібраний із цих
чисел, належить саме цій гарнітурі.

### Що диктує клітинка

Клітинка 12×18, один піксель по периметру зарезервовано під обводку — отже на
роботу лишається 10×16. Звідси три правила:

- **Знаки стоять над лінією великих літер.** У кожної з десяти гарнітур там є
  щонайменше три рядки, тож знак ніколи не тиснуть. Кільце над Å хоче третій:
  де в гарнітури є запас знизу, літера опускається на рядок, а в найвищої
  кільце стає на два рядки, відкрите знизу, щоб зберегти просвіт.
- **Знаки під базовою лінією піднімають літеру.** `extra_large` дістає до
  низу клітинки, тому Ç Ę Ș піднімаються на рядок-два, аби не втратити знак.
  Це той самий прийом, яким кирилиця рятує хвостик Ц і Щ.
- **Блоки навмисно доходять до стіни.** Псевдографіка мусить стикуватися із
  сусідньою клітинкою, тому `scripts/blocks.py` — єдиний набір, що ігнорує
  поле.

### Символи, які розкладаються на літери

Æ, ß, ©, ™, № і прості дроби не влізають у клітинку на 12 пікселів, а якби
влізли — були б нечитними. У кожного є запис у `FOLDS` із літерами, які він
означає, і GSUB його розкриває: `Æ` стає A E, `№` стає N °. Сам кодпойнт при
цьому несе копію контуру першої літери, тож рендерер без GSUB покаже A, а не
дірку.

## Кирилиця

`scripts/cyrillic.py` додає 37 великих літер, яких у Betaflight немає. Вони не
намальовані з нуля: кожна збирається з власних латинських форм того самого
шрифта, тож товщина й пропорції переносяться самі.

- 14 літер це латинський гліф як є (А В Е І К М Н О Р С Т Х У, а З з цифри
  три), 2 це дзеркальні (И з N, Я з R).
- Решта складається з частин, які у шрифта вже є: Г це верхня перекладина зі
  стійкою, П додає другу стійку, Ш третю, Щ і Ц хвостик, Ф це О зі стійкою
  всередині, Ж це Х із тією ж стійкою.
- Складається лише біла серцевина, чорну обводку добудовує `outline()`.

Три речі, які диктують самі шрифти:

- **Ширина.** Три стійки й два просвіти не вміщаються в латинську ширину
  кількох шрифтів, тому Ж Ш Щ Ю Ы отримують ширшу коробку. Без цього стійки
  зливаються в суцільну пляму.
- **Нахил.** betaflight курсивний. Побудова йде на випрямленій копії, а
  результат нахиляється назад, бо інакше частини з різних літер сходяться зі
  зсувом, а дзеркальні літери хиляться не в той бік.
- **Запасні форми.** Де форма не працює, літера бере другу: Ж стає трьома
  стійками, з'єднаними на поясі, якщо рамена поглинають центральну стійку, а З
  малюється замість запозичення там, де цифри вищі за літери.

У `.mcm` нічого з цього не потрапляє: із 256 слотів зайнято 222, абетка туди не
влазить, та й OSD її не покаже.

## Кольорові гліфи

Колір дають `COLR` v0 / `CPAL` з палітрою на два записи: чорний і білий.
Кожен символ це три гліфи:

| Гліф | Що в ньому |
| --- | --- |
| `bfXX` | силует, базовий гліф; його малюють ті, хто не знає `COLR` |
| `bfXX.black` | силует, колір з індексу 0 |
| `bfXX.white` | лише білі пікселі, індекс 1, малюється зверху |

Білий шар лежить поверх **повного** чорного силуету, а не поруч із самими лише
чорними формами. Дві заливки різного кольору встик лишають волосяні щілини від
згладжування на шві; з перекриттям такого немає.

Програми, які не читають `COLR`, малюють базовий гліф, тому Figma й показує
пласкі одноколірні літери. Для них пласкі гарнітури будуються типово
(`--no-layer-fonts` їх пропускає), і кожен шрифт виходить ще у двох пласких
гарнітурах: у `Shadow` кожен гліф це силует, у
`Fill` лише білі пікселі. Вони з тих самих контурів і метрик, що й кольоровий
шрифт, тож два накладені текстові шари дають точно його.

`COLR`/`CPAL` не залежать від формату контурів, тому однакова побудова йде і в
CFF `.otf`, і в `glyf` `.ttf`. Вебфайли це той самий TTF, загорнутий у WOFF і
WOFF2: у контурів `glyf` ширша підтримка кольорових шрифтів.

## Метрики

| | |
| --- | --- |
| Одиниць на em | 1800 (100 одиниць на піксель OSD) |
| Ширина символу | 1200 (12 пікселів), моноширинний |
| Верхній / нижній виносний | 1400 і -400, 18-піксельна клітинка вміщається між ними |

Ліві напівапрош (`lsb` у `hmtx`) беруться з реального `xMin` кожного гліфа.
TrueType позиціонує гліфи саме за `lsb`, тож глухий нуль зсуває кожен гліф убік.

## Мапа символів

- `U+E000 + індекс` дає всі 256 символів, завжди.
- `0x20-0x7E` додатково мапляться на свої ASCII-кодпойнти, плюс `U+00A0` на
  пустий символ.
- `a-z` зведені на великі літери, бо малих у Betaflight немає, а в тих слотах
  лежать стрілки й символи. `--literal-ascii` лишає їх на своїх місцях; у
  будь-якому разі ці символи доступні за своїми `U+E0xx`.
- Малі літери зводяться на великі в кожному письмі, за таблицею `LOWERCASE`
  відповідного набору.
- Іконки, які збігаються зі стандартним символом, дістають і його — з
  `symbols.ALIASES`: стрілки компаса на `U+2190`-`U+2199`, дім на `U+2302`,
  ℃ і ℉, мітки хвилин і секунд GPS як штрих і подвійний штрих. Намальований
  гліф завжди має пріоритет над аліасом.
- У `$`, `~` і `` ` `` вихідний шрифт тримає картатий прапорець, приціл і
  стрілку. `scripts/punctuation.py` малює ті символи, на честь яких ці
  кодпойнти названі; іконки лишаються за своїми назвами та `U+E0xx`.

## Іконки та фічі OpenType

`scripts/symbols.py` — це каталог: кожен нелітерний символ вихідного шрифта з
назвою, групою та стандартним кодпойнтом, якщо він на нього заслуговує. Назви
йдуть за `osd_symbols.h` із прошивки Betaflight там, де малюнок збігається,
і за тим, що намальовано насправді, там, де ні: вкладені шрифти старші за
частину перестановок у тому хедері, тож `0x70` досі іконка часу, а не швидкості.

Через `feaLib` збираються дві фічі:

| Фіча | Що робить |
| --- | --- |
| `liga` | `:battery:` та інші 189 назв стають своєю іконкою |
| `ccmp` | розкладені символи розгортаються |

Складники лігатур беруться з cmap тих символів, які реально набирають, тож
`:sat_left:` працює і зі зведеними `a-z`, і з буквальними, а на тексті на кшталт
`12:30:45` правила не спрацьовують, бо кожне починається й закінчується
двокрапкою. З `--no-ascii-cmap` фічі не будуються взагалі: без ASCII немає
двокрапки, яку можна набрати.

`docs/SYMBOLS_UA.md` генерується з каталогу:

```bash
uv run tools/symbol_index.py   # docs/SYMBOLS.md, docs/SYMBOLS_UA.md, docs/logo.png
uv run tools/specimen.py       # docs/sets.png
uv run tools/favicon.py        # site/assets/favicon.png
```

Фавіконка — це квадратний виріз із `#`, а не сам PNG символу: PNG-и це комірки
12x18, і браузер втискає таку картинку в квадратне гніздо.

`docs/social-preview.png` не генерується. Це картинка, яку завантажують руками
в Settings -> General -> Social preview; вона лежить тут, щоб у репозиторії
лишалася копія того, що він показує.

## Робота над скриптом

```bash
uv sync --group dev
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run mypy
```

CI ганяє те саме на кожен пуш: лінт (ruff і mypy), тести на Python 3.10 і 3.14,
і збірку, яка перегенеровує всі вкладені шрифти й порівнює результат із
закоміченим `output/` через `tools/compare_output.py`.

Шрифти та JSON звіряються побайтово, і це працює, бо `SOURCE_DATE_EPOCH`
зафіксований у скрипті, інакше fontTools пише в `head.created` поточний час.
PNG натомість звіряються по декодованих пікселях: колеса Pillow під різні
платформи несуть різні збірки zlib-ng, тому deflate-потік у macOS і Linux
різний навіть за однакових пікселів.

## Як перевірити зміни

Контури точно оборотні, тому круговий прогін це основний тест:
`tests/conftest.py` растеризує протрасовані контури за правилом ненульового
заповнення в центрах пікселів і порівнює з вихідним растром. Набір робить це
для обох шарів усіх 256 символів у десяти вкладених шрифтах, тобто 5120
наборів контурів.

Решта тестів покриває парсинг, мапу символів, метрики і одну регресію, яку саме
порівняння контурів не побачить: ліві напівапрош у `hmtx` мають збігатися з
`xMin`, інакше TrueType зсуває кожен гліф убік.

У `tests/test_sets.py` зібрані правила, яких мусить дотримуватись кожен
зібраний набір у всіх десяти шрифтах: нічого порожнього, нічого на стіні
клітинки, жодних двох кодпойнтів з однаковою формою, літера з діакритикою
містить свою літеру цілком, а кожен запис у `NAMES` збігається з тим, як цей
кодпойнт називає Unicode — саме це ловить помилку в кодпойнті ще до того, як
хтось його набере.

`tests/test_symbols.py` проганяє текст через HarfBuzz, тож лігатури й
розкладені символи перевіряються так, як їх виконає справжній рендерер.

Рендер це єдине, чого тести не перевіряють. `ImageFont` з Pillow і
`embedded_color=True` растеризує `COLR`/`CPAL` через FreeType, і це швидкий
спосіб глянути очима на помилки в шарах та палітрі.
